IV.A Functions IV, Q2: Keyword Arguments

Learning Objectives

  • Trace a default set across repeated calls.
  • Explain why a None default avoids shared mutable state.

Background

A keyword argument supplies a value by parameter name, for example words_to_include=chosen. If a caller omits that argument, Python uses the default from the function signature (the first line of the definition). Defaults are evaluated once when the function is defined. A set is mutable: .add() changes the existing object. Consequently, words_to_include=set() creates one set shared across omitted-argument calls. Using None as a sentinel lets the function create a new empty set inside each such call. This activity makes that difference visible through two calls, rather than testing the loop in the notebook.

One default, many calls

Does a new call get a new set?

This short example adds a word to a set. Compare the same calls with two different defaults.

A. A set in the signature

def remember(word, words_to_include=set()):
    words_to_include.add(word)
    return words_to_include

B. None in the signature

def remember(word, words_to_include=None):
    if words_to_include is None:
        words_to_include = set()
    words_to_include.add(word)
    return words_to_include

    What if the caller supplies a set?
          
    Both versions use the caller's set directly. None creates a new set only when the argument is omitted or explicitly None; it does not copy a supplied set.

remember("cat", words_to_include=chosen)
