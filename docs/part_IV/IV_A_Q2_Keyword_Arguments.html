IV.A Functions IV, Q2: Keyword Arguments

Learning Objectives

  • Trace a default set across repeated calls.
  • Explain why a None default avoids shared mutable state.

Background

Python creates a default value once, when a function is defined. If that value is a set and the function changes it, later calls reuse the changed set. A None default lets the function create a fresh set inside each call instead.

One default, many calls

Does a new call get a new set?

Both versions receive the same words, one call at a time. Each call supplies only word, so Python uses the default for words_to_include. The default follows = in the first line of each definition. A keyword argument would supply a value by name, such as words_to_include=chosen; these calls omit it. The .add() line changes the set.

A. A set in the signature

def remember(word, words_to_include=set()):
    words_to_include.add(word)
    return words_to_include

B. None in the signature

def remember(word, words_to_include=None):
    if words_to_include is None:
        words_to_include = set()
    words_to_include.add(word)
    return words_to_include

    What if the caller supplies a set?
          
    Both versions use the caller's set directly. None creates a new set only when the argument is omitted or explicitly None; it does not copy a supplied set.
    
          
    chosen = {"bird"}
remember("cat", words_to_include=chosen)
# chosen is now {"bird", "cat"} in both versions.
